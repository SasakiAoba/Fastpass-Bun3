# 文化祭カジノ企画 ファストパス管理システム

このリポジトリは、木製ファストパスの販売、発番、入場、使用済み取消、払い戻し、会計、記録を扱う管理画面です。

現在の実装は、Cloudflare D1へ接続する前の **localStorage確認版** です。業務データは利用中のブラウザー内だけに保存されます。

## 最初に確認する設定

単価、表示接頭辞、最大番号、日別上限、開催日は、次の1ファイルに集約しています。

```text
src/config/fastpass.config.ts
```

現在の主な設定は次のとおりです。

- 単価：100円
- 番号：`HC-001`～`HC-200`
- 日別上限：各日200枚の仮値
- 開催日：3日とも未設定
- 仮確保：180秒

開催日未設定中、LIVEモードの新規販売は仕様どおり停止します。画面確認と販売試験は、管理画面から開発者モードを開始して行ってください。

## localStorage確認版の重要な制限

この段階は、単一端末で画面と業務ロジックを確認するためのものです。本番の複数端末運用には使用しないでください。

- MacとiPadのデータは共有されません。
- 複数のiPad間でデータは同期されません。
- SafariとChromeのデータは共有されません。
- Preview URLとProduction URLのデータは共有されません。
- ブラウザーのサイトデータを消すと、保存した業務データも消えます。
- 端末時刻を使用するため、本番のサーバー時刻保証はありません。
- localStorageにはD1と同等のトランザクション・端末間排他がありません。
- ローカル認証は操作フロー確認用です。開発者ツールからの改変を防ぐ本番認証ではありません。

画面上にも「ローカル確認版・端末間同期なし・本番運用不可」と常時表示します。

## ローカル専用パスワード

初回起動時に、確認版専用のパスワードを設定します。

- 10文字以上
- 大文字を1文字以上
- 小文字を1文字以上
- 数字を1文字以上

平文は保存しません。ソルト付きPBKDF2-SHA-256検証値だけをlocalStorageへ保存します。ただし、クライアント上の仕組みであるため、本番のセキュリティ境界にはなりません。

ログイン成功後は、画面の再読み込み、端末のスリープ、長時間の無操作ではログアウトしません。払い戻し、使用済み取消、管理操作でもパスワードを再入力せず、内容確認だけを表示します。ヘッダーの「ログアウト」を押した場合に限り、次回のログインでパスワードを求めます。共有端末では、運用終了時に必ずログアウトしてください。

仕様書に書かれた本番用初期パスワードは、コード、Git、README、SQLへ転記しません。D1版では、別の非公開初期化手順からArgon2idハッシュを登録します。

## 開発

Node.js 20以上を使用します。

```bash
npm install
npm run dev
```

表示されたローカルURLをブラウザーで開きます。

## 検査

```bash
npm run typecheck
npm test
npm run build
```

本番ビルド結果は `dist/` に生成されます。`dist/` はGitへ追加しません。

## Cloudflare Pages

localStorage版は静的なVite SPAとしてデプロイできます。

| 設定 | 値 |
|---|---|
| Production branch | `main` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | リポジトリルート |

`public/_redirects` はSPAの再読み込みを `index.html` へ戻します。`public/_headers` は静的配信向けの基本的なセキュリティヘッダーを指定します。

現段階ではPages Functions、D1、D1 Bindingを使用しません。

## 主な操作

### 販売

1. 管理画面で開発者モードを開始します。
2. 販売画面で人数をテンキー入力し、カートへ追加します。
3. 「会計へ進む」で180秒の仮確保を作ります。
4. 預り金を入力し、「会計確定・発番」を押します。
5. 表示番号、木製券、釣銭を照合します。
6. 「受渡しを確認して次の会計へ」を押します。

### 入場

1. 入場受付画面で、実物の券番号を追加します。
2. 対象一覧を確認します。
3. 全券を一括確定します。
4. 成功表示後に入場させ、券を回収します。

### 使用済み取消・払い戻し

どちらも実行前に、パスワード入力のない確認画面を表示します。ログイン後の操作でパスワードを再入力することはありません。

払い戻しは未使用券だけが対象です。払い戻しても、販売済み枚数と発行済み番号は戻りません。

### 会計

会計画面には金額入力欄を置かず、販売時に記録した預り金とお釣りから自動集計します。

- もらったお金：各会計の預り金額の合計
- お釣り：各会計のお釣りの合計
- 売上金額（払戻前）：もらったお金 − お釣り
- 最終金額：売上金額 − 払い戻し金額
- 販売枚数、会計件数、払い戻し枚数
- 1～3日目と全期間の内訳

経費、釣銭準備金、現金補充、売上金回収、現金実査は画面から入力しません。旧localStorageや復旧用JSONとの読み込み互換性のため、既存の現金・経費データ項目はローカル版の内部形式に残していますが、新しい会計表示の計算には使用しません。

### 開発者モード終了

開発者モード終了時、現在のDEV領域のチケット、販売、入場、返金、現金、経費、操作結果、履歴を削除します。LIVE領域とローカル認証情報は保持します。終了後はLIVEの営業停止状態になります。

## バックアップと出力

管理画面から次を出力できます。

- 本番領域JSON
- チケットCSV
- 販売CSV
- 払い戻しCSV
- 操作履歴CSV
- localStorage確認版の復旧用JSON

正式な本番出力へDEVデータは含めません。復旧用JSONにはローカル業務データが含まれるため、取扱いに注意してください。ローカル専用パスワードの検証値は含めません。

## D1移行について

localStorage確認版のデータはD1へ移行しません。

画面確認と静的Pages版の確認後、次の段階で空のD1を作成します。

- Productionデータベース名：`bun2fastpass`
- Previewデータベース名：`bun2fastpass-preview`
- Binding変数名：`DB`

D1へ適用する初期スキーマ案は `migrations/0001_initial.sql` にありますが、会計簡略化後のローカル画面確認が終わってから最終設計へ合わせて整理します。このSQLはまだどのD1にも適用しません。認証情報の行やlocalStorageの確認データも含みません。

実際の適用は、Pages Functionsによるサーバー側の業務処理を実装し、Preview用D1で受入試験を通してからProductionへ進めます。初期パスワードのハッシュ登録はSQLファイルとは分離した非公開手順で行います。

D1段階ではSQLマイグレーション、Pages Functions、サーバー認証、HttpOnly Cookie、CSRF対策、サーバー時刻、原子的な発番、複数端末競合、冪等結果照会を実装します。

発番、販売日、単価、残数、対象領域をブラウザーから信頼する構成にはしません。
